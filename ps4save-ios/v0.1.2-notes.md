## v0.1.2 — folder-picker fix for sideloaded installs

### Fixed
- **System folder picker (Encrypt → Browse → folder → Open)** no longer
  dead-ends on iOS 26.x installs signed with on-device self-signing tools
  (Feather et al.): the Open-in-place grant path stalls on those installs.
  Two answers ship in one binary: a **file-boxes flow** (pick the save
  files and the sce_sys contents in two multi-select file boxes — copy
  semantics proven to work on such installs — and the app rebuilds the
  folder layout, `sce_sys/param.sfo` gate included) plus the legacy
  Import pipeline for the folder picker itself (`UIDocumentPickerModeImport`),
  the same repair the ecosystem's picker fixes force via runtime
  injection, applied in-binary and default-on.

### Also in this build
- Scene-lifecycle migration with classic-launch fallback
- `CFBundleDocumentTypes` registration (`public.directory`,
  `public.folder`; mirroring the working App Store implementation)
- `UISupportsDocumentBrowser` contract key
- In-app sandbox folder browser (SaveBrowserVC) for Documents-resident saves
- File-pair multi-pick flows unchanged
- Ships **zero** console keys — config ships keyless; keys stay on disk

### Notes
- Ships with `config.example.ini` (keyless template); place your own
  `config.ini` via the Files app → this app's Documents folder
- If you sideload via Feather: enable its "files app support" toggle
  (writes `UISupportsDocumentBrowser`) — harmless either way since the key
  ships baked in
